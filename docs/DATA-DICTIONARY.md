# 数据定义

票号与原始编号均为字符串，保留前导零。称重支持 kg、公斤与 t，统一为 kg，单价为 CNY/kg。
毛重与皮重按票号和版本配对，品类、单价、扣杂率与更正目标必须一致。计价重量=(毛重−皮重)×(1−扣杂率)，先量化到0.001kg，再乘单价，金额四舍五入到0.01CNY。
每票第一版不填写 replaces。后续版本只能替代当前生效版，分支或缺基版整票阻断结算。已支付额为各版本中最大累计已付值，待付=最终应付−累计已付；负待付表示待收回。
同编号同原值仅计一次；同编号不同原值全部隔离。空文件、全空行和仅表头分别报错。原始输入计数包括空行及重复表头，对账会分别解释。

## 可开票结果与开票台账

更正裁决与对账之后生成每票可开票快照（`state.invoiceable`），冻结开票当时的生效版本与金额；快照之后不受重算影响。任一闸门命中的票不进入可开结果，落入 `state.invoice_blocked` 待处理票：

- `DUP_INVOICE_NO`：发票号被其他票占用（数据库部分唯一索引强制，作废号除外）。
- `BROKEN_CHAIN`：更正缺前版或版本冲突，唯一生效版无法确定。
- `AMOUNT_UNBALANCED`：生效应付 ≠ 已付 + 待付，金额未对平。

可开票金额 + 待处理票金额 = 生效应付总额（守恒，不丢票、不重计）。开票台账为只追加事件日志（`invoice_events`：issue/published/adjust/voided）加发票现状投影（`invoices`）。同一票同版本重跑幂等，不重复开票；事件与投影在同一事务写入，发布中断整体回滚，残留 `publishing` 由 `POST /api/runs/{id}/invoices/resume` 恢复旧版记录并留 voided 痕。后到更正不改写已开发票，重算后按"最终应付 − 已开净额"开调整票，正数补开、负数红冲。事件表只 INSERT，原始输入字节、版本链与票据事件全程留存；封存包 `evidence.json` 随附完整开票台账。

归档封存保存逐版证据、隔离原因、开票台账和运行摘要，非支付执行系统。数据使用虚构编号，不连接实际支付渠道。
